# Diagram Director

Dataset-driven generator for free-style (non-UML) animated system-design diagrams: architecture,
request lifecycle, data pipelines, infra topology. Output is self-contained HTML with inline SVG and
CSS/JS motion showing *how the system behaves* — traveling packets, filling queues, pulsing nodes —
not just what it contains.

## When to Apply

Any request to draw, visualize, explain, or improve a system's architecture, request/data flow,
pipeline, deployment/infra topology, or "how does X work" behavior — including improving an existing
diagram's clarity or motion. The test is the CAST: the boxes are deployed software components
(services, queues, stores, nodes). STEP 0 below settles that before anything else.

## When to Skip

- Formal UML class/ER diagrams where a strict notation is explicitly required (this skill is
  free-style, not UML-compliant).
- Charts of quantitative data (bar/line/pie) — that's data visualization, not system topology.
- UI/product interface mockups — use `ui-ux-pro-max` instead.
- Pure prose explanation with no visual deliverable requested.
- **Boxes that are people, documents, work items or approval steps** (onboarding, an editorial
  flow, a review workflow) are NOT skipped any more — they are the `process` genre of STEP 0, drawn
  with `--genre process`. Its cuts are held to the same bar as any other. What is
  still wrong is drawing them WITHOUT the flag, as services and queues. Also not skipped: a
  protocol or algorithm MECHANISM
  (a handshake, a consensus round, a backoff scheme) is `system-design`, drawn with the existing
  `sequence-flow`, `state-machine` or `auth-flow` types.

## Workflow — Solve, Storyboard, then Draw

Visual work never starts on an unsolved solution. Five phases, in order (full contract with the
solution-sheet format: `references/workflow-phases.md`; the Phase-1 audit checklist and the other
genre-specific authoring rules: `references/genres/<genre>.md`):

| Phase | Do | Gate to pass |
|---|---|---|
| 1 Research + solve | Ask the architecture-changing questions first (scale, guarantees, constraints). For non-trivial `system-design`, then pass the genre's **research + source-lock gate** (primary sources, comparable production cases, fact/inference/assumption labels). Write the **solution sheet** last: components + responsibilities, counts, all numbers, one owner per guarantee. | Source lock + race / recovery / pre-condition audits pass |
| 2 Storyboard | Beat budget from component count; per-beat frame (with upstream node), caption, morph, zoom k. **Every caption restates a sheet claim — never a new fact.** | Coverage, upstream, ownership, counts, cluster-vs-singleton audits |
| 3 Visual system | Target (STEP 1 below), then `--blueprint`, style, layout, component shapes; count N → replica stack. | Routing table concerns answered from the dataset |
| 4 Build | Template copy, hand-placed coordinates, motion budget, beats keyframes generated by a loop. | — |
| 5 Verify | Render and LOOK at every beat hold; full pre-delivery checklist; **text-sync sweep**: every number and guarantee-claim in the file traces to the sheet; diff strings on every fork. | Checklist green |

**The sync rule:** the solution sheet is the single source of truth for every string — labels,
subs, edge labels, captions, morph interiors, `<desc>`. A solution change edits the sheet first,
then re-flows everywhere; a string that cannot be traced to a sheet line does not ship. For a quick
static diagram, phases 1–2 collapse to a mini-sheet — never skipped.

## STEP 0 — What Are the Boxes? (genre)

Before the target, before the type: decide what the boxes ARE. That is the **genre**, and it picks
which corpus the question is asked of — not a style, not a filter on the answer. `--genre` carries
the decision into every search (`system-design` is the CLI default), and the genre's own authoring
rules live in `references/genres/<genre>.md`, read alongside the engine references.

| The boxes are | Genre | Types it answers with | Status |
|---|---|---|---|
| services, queues, databases, caches, gateways, nodes — deployed software | `system-design` | the other 17 | shipped, and the default |
| people, roles, documents, work items, steps, approvals, decisions | `process` | `process-loop` | **shipped** |

**If the answer is `process`, use it.** The pack is here (guide `references/genres/process.md`, one
type, ten components, its own shapes), so `--genre process` composes a real blueprint and every
engine gate applies unchanged. Checklist item 16 diffs a new process cut's presentation layer
against the genre's snippets (`templates/snippets/process-stations.html` + `.css`); the guide's
*Idiom authority* section says exactly what it covers. Read the guide before building: the
construction mode is **HTML stations + a thin SVG
overlay for connectors only**, which is not how any system-design cut is built. Do **not** re-cast
the request as system-design either way: drawing an approval chain as
services and queues mislabels every actor on the canvas. The one thing that only LOOKS like process
is a request naming a workflow *tool* (a CI pipeline, a k8s rollout) whose boxes are still deployed
software — that is `system-design`, proceed.

## STEP 1 — Decide the Target Before Anything Else

This is the single highest-impact decision. Getting it wrong renders a blank diagram.

| Target | When | Constraint |
|---|---|---|
| `artifact` | Output is a published Claude Artifact | CSP blocks external scripts: **css-only techniques only, zero CDN scripts.** `hand-drawn-sketch`'s rough.js path is OFF the table (use its `feTurbulence` fallback). Motion is barely limited any more: all but one of the motion patterns now ship as CSS classes, leaving only `shard-distribute` as `needs-js`. Trust `motion.csv → Runtime` rather than memory here — several motions were `needs-js` before their CSS forms shipped. **Google Fonts is the one permitted exception** — stylesheets from `fonts.googleapis.com` and the font files they pull from `fonts.gstatic.com` load normally, so keep the `<link>` and always pair it with a real fallback stack. |
| `local` | Output is a `.html` file the user opens in a browser | CDN allowed — rough.js for hand-drawn-sketch, Google Fonts. |

If unsure, ask; if unable to ask, **default to `artifact`** — it renders everywhere, `local` does not
degrade gracefully in a CSP sandbox. Pass the decision to `search.py` via `--target`; it enforces the
constraint (`--target artifact` returns only `Runtime=css-only` rows with empty `CDN Deps`) in
`--blueprint` **and** in plain `--domain` searches of the two datasets that carry a `Runtime` column
(`styles`, `motion`); every other domain is unaffected because a layout or a payload has no runtime.
A withheld row is never silent: the output names it and says `re-run with --target local`, so a
0-result under `--target artifact` is a delivery constraint, not an empty database. The CLI default
is `artifact` too, so an omitted flag lands on the same safe answer this table names — pass
`--target local` deliberately, never by leaving the flag off.

## Priority Routing Table

Query the domain that answers each concern, in this priority order:

| Priority | Concern | Domain | Must Get Right | Anti-Pattern |
|---|---|---|---|---|
| 1 | Is this the right *kind* of diagram? | `types` | Type matches the question being answered | Drawing infra topology when asked about request flow |
| 2 | Which layout/arrangement? | `layouts` | Flow direction + spacing numbers + node-count fit | Arbitrary coordinates; crossing edges |
| 3 | What do the boxes mean? | `components` | Semantic role + shape hint + label convention | Generic rectangles for everything |
| 4 | What does the motion *say*? | `motion` | Motion semantics match edge semantics | Animation with no meaning; everything moving at once |
| 5 | What is *traveling* on this edge? | `payloads` | Glyph from the row's Glyph Ref; edge label still names the cargo | Every flow as the same dot when the cargo differs; icon-only cargo |
| 6 | How do I show a component's *condition*? | `states` | All three layers: static + chip, motion (FK'd recipe), reduced-motion resting visual | Meaning that survives only in motion; a bare red glow with no chip or number |
| 7 | Which visual style? | `styles` | Purpose fit (teaching vs formal docs) + runtime fit | Style that needs JS in an Artifact |
| 8 | Which colors? | `colors` | Role coloring + AA contrast + dark variant; a style may ship several named palettes — use its `Default Palette` (`house`) unless the user asks for another by name | Color-only encoding; decorative palettes; mixing two palettes in one diagram |

Comparison prompts ("with vs without X", "so sánh") and progressive-scale prompts ("from 0 to
500K CCU") partition the canvas into territories — read `references/multi-pane.md` before
storyboarding those.

## Running the Search Tool

**Run every command from the REPOSITORY root, with the relative path shown.** The scripts resolve
`data/` from their own location, so the same invocation works wherever the skill is checked out —
no environment variable, no absolute path, nothing machine-local to keep in sync. (When this skill
is installed standalone at `~/.claude/skills/diagram-director`, drop the `diagram-director/`
prefix: everything after it is skill-relative.)

```bash
python3 diagram-director/scripts/search.py "<query>" --domain styles|types|motion|components|states|payloads|colors|layouts [-n 1-20] [--genre system-design|process] [--json] [--full]
python3 diagram-director/scripts/search.py "<scenario>" --blueprint [--type <type-id>] [--style <style-id>] [--target artifact|local] [--genre system-design|process] [-f markdown|ascii] [--json]
python3 diagram-director/scripts/validate_csv.py [--counts]
python3 tools/calibrate_floors.py [--sweep]                    # replay tests/probes/*.tsv; run this after ANY floor or keyword change
python3 diagram-director/scripts/verify_edge_anchors.py <generated.html> [--tol 12]   # anchoring AND nearest-side
python3 diagram-director/scripts/report_keyword_df.py [--domain <d>] [--top 15]   # advisory keyword-quality report, never a gate
python3 diagram-director/scripts/verify_all.py <cut>.html --serve [--target artifact|local] [--json]
node diagram-director/scripts/browser-checks/verify-staged-windows.mjs <url> [--acts] [--reduced-motion]
node diagram-director/scripts/browser-checks/verify-html-edge-anchors.mjs <url> [--tol 12]   # HTML-mode (process) edges
node diagram-director/scripts/browser-checks/verify-caption-occlusion.mjs <url> --manifest <cut>.manifest.json   # card vs the scene under it
node diagram-director/scripts/browser-checks/contact-sheet.mjs <url> --manifest <cut>.manifest.json --out <dir>
```

`--json` is the machine half of the same run: one envelope on stdout (`schemaVersion 1`) with
`ok`, the process `exit`, every stage row, and a `diagnostics[]` whose entries carry a STABLE
`code` (`diagram-director/scripts/diagnostic_codes.py`), measured `evidence`, and `supportedFixes` sentences that
were proven by re-solving — a failing camera hold reports the `k/tx/ty` that passes, not advice.
Repair off THAT, never off the prose table. **Repair is bounded.** Count objective errors
(`diagnostics` with severity `error`). Continue only while that count reaches a NEW MINIMUM. Two
consecutive rounds without a new minimum → stop and report truthfully what still fails. A verify
that passes FREEZES the cut: no further edits without re-running the whole runner. And deleting a
declaration is not a repair — stage A fails a manifest whose `features`/`holds` shrank against the
committed one without a dated AMENDMENT in the sheet.

`verify_all.py` is the one runner for delivery: it reads the cut's manifest, decides which
render-side checks are mandatory from the declared feature list, and orchestrates
`validate_manifest.py`, the stdlib structural checks, every `browser-checks/*.mjs`, and
`solve_camera.py --check` over every declared hold. Exit `0` all green, `1` a failure, `3` the
render-side stages could not run (an UNVERIFIED cut). It does not replace the eye:
**generating the contact sheet and looking at it is mandatory before delivery**
(`references/pre-delivery-checklist.md` item 18) — curves, style fidelity and semantic truth are
reviewed there and nowhere else.

If `python3` is not found, try `python`, then `py -3`. Python 3.x, no external dependencies.

The `node` checks need puppeteer, which this skill does **not** depend on: they resolve it from
`PUPPETEER_RESOLVE_DIR` or a plain `import("puppeteer")`, and when neither is available they print
`UNVERIFIED -- puppeteer not available` and exit `2`. Exit 2 is not a pass — **say in the delivery
message which checks did not run** (`diagram-director/scripts/browser-checks/README.md`).

## Query Contract

1. **New diagram → `--blueprint` first, always**, with `--genre` from STEP 0 and `--target` from
   STEP 1. It returns a
   9-section spec (Meta, Component catalog, Edges & semantics, Layout rules, Motion assignments,
   Palette tokens, Template to copy, Checklist, Warnings).

   ```bash
   python3 diagram-director/scripts/search.py "how a checkout request reaches the database" --blueprint --target artifact
   python3 diagram-director/scripts/search.py "onboarding approval flow for new employees" --blueprint --genre process --target artifact
   ```

   The second line is the whole difference STEP 0 makes: **the same scenario without `--genre
   process` abstains** — the system-design corpus has no type whose cast is people and documents,
   and that abstain is the correct answer, not a miss to work around by naming a type.
   **Know what the blueprint is authoritative for:**

   | Section | Authority |
   |---|---|
   | diagram **type**, **layout**, **style**, **palette** tokens, edge semantics, motion set, anti-patterns | **Authoritative.** Use as returned. |
   | the **component catalog** (section 2) | **Illustrative only — never a paste list.** It expands the type's `Node Kinds` cell, which freezes ONE worked example of the archetype: `comparison` carries a chat-fanout example, so pasting it drew browsers and a websocket mesh for an *auction* prompt while every geometry gate stayed green (observed). |

   **STYLE: the blueprint is authoritative ABSENT a user constraint.** With no instruction about
   look or register, the returned style ships — "I preferred another one" is not a reason. But an
   EXPLICIT user constraint on style or register wins over it: a named style, a named register
   ("educational, not a comic"), or a ruled-out look ("don't imitate that hand-drawn poster"). When
   it wins, **do not hand-pick tokens — re-run `--blueprint --style <x>`** so layout, palette,
   motion set and edge semantics still come from the tool for the style you are actually drawing,
   and record the override in the sheet's DEVIATIONS with the constraint that forced it. The first
   process cut did exactly this: the blueprint returned `comic-storytelling`, the user had asked
   for an educational register and ruled the poster look out, so it re-ran `--blueprint --style
   flat-minimal` and took everything else as returned.

   **The component list always comes from per-component `--domain components` queries** — one query
   per component on the solution sheet — recorded in the Phase 3 mapping table
   (`references/workflow-phases.md` → Phase 3). Draw only shapes that trace to a row in that table.
   Reasoning a shape from memory shipped a browser without its device chrome and an event-bus as an
   invented drum, also with every gate green (observed). A catalog entry earns a table row only when
   the same Component ID comes back from your own query.
2. **If `--blueprint` ABSTAINS, it composed nothing** — no type cleared the score floor, and there
   is deliberately no default (a guessed type drags a wrong layout, motion set and edge semantics
   behind it). Re-run with `--type <type-id>`, or rephrase the scenario naming what is being shown.
   Never continue on a type you picked from memory without saying so.
3. **Targeted follow-up concern → one `--domain` search**, not `--blueprint` again. Carry the same
   `--genre` on the two domains that partition by it (`types`, `components`) — the other six are
   shared, so the flag is a no-op there.

   **The cross-genre pointer is an EXACT-ID feature, and nothing more.** It fires only when the
   whole query string equals a row's Component/row ID or one of its pipe-listed `Aliases`, case
   folded (`diagram-director/scripts/id_lookup.py` → `cross_genre_pointer`). `cache` under `--genre process` gets
   the pointer; **`postgres database store` under `--genre process` gets a plain 0 and no
   pointer at all**, because a described need is a miss, not a named row (measured: the first
   process cut ran exactly that and read the silence as a bug in the pointer). So a 0 result
   never means "this concept exists in no genre" — to ask that question you must type the ID.
   Ranked search never mentions the other corpus either way.
4. Use 2–5 meaningful terms, one dominant intent. Verify the returned domain and top-1 identity before
   using it.
5. **Always pass `--domain` explicitly.** That is the contract. Omitting it does NOT pick a domain for
   you: auto mode is a *helper that names candidates*, and when no domain leads the runner-up by the
   routing margin it prints `Auto-routing did not find a clear domain` with the ranked candidates and
   **searches nothing**. It used to tie-break silently, and measured against the 48 smoke queries'
   recorded domains it was wrong 31 times. Read the candidates, then re-run with `--domain`.
6. **`-n` is targeted by default (`-n 1`).** A component lookup has one right answer, and the second
   and third rows were being read as alternatives worth using. `-n > 1` is the single opt-in for
   alternatives, and it is honest about them: **every returned row cleared the domain score floor on
   its own** (rows below it are dropped, not greyed out) and the **raw score is printed next to each
   result**. So `Found: 1` after `-n 5` means the dataset has exactly one answer, not that four are
   hiding below a cutoff.
7. **Retry once** with a narrower rewrite or explicit `--domain` if the result is empty or off-topic.
   **The retry runs in exploration mode: `-n 5`.** Narrow first, widen second — a targeted miss
   followed by a wide look is what distinguishes "wrong words" from "no such row".
8. **If a search still returns 0 results after the `-n 5` retry: say so explicitly.** State plainly that
   no verified match was found, and label anything you produce afterward as a fallback, not as data from
   this dataset. **Never present a 0-result search as if it returned data.**
9. **Record every 0-result and every rejected false friend in the solution sheet.** Both are findings.
   A 0 for `polling` is the dataset telling you to model a cadence on the edge, not an invitation to
   substitute `cron-job`; the sheet row reads `NO ROW — custom shape` or `NO ROW — cadence on edge`,
   and the delivery message repeats it. A false friend you *considered and rejected* gets written down
   too, so the next pass does not re-litigate it.
10. **Colour lookups are composite, not fuzzy.** `--domain colors` with a Style ID in the query returns
    **one logical palette — all 7 role rows** of that style's `Default Palette`. Name a palette
    (`"blueprint showcase palette"`) to get that one instead, or a role (`"neon-dark client"`) for a
    single row. Free-text colour search still works for exploration; it is the Style ID in the query
    that switches on the exact lookup. Never mix roles from two palettes into one diagram.

## Output Rules

- Self-contained single HTML file by default. Split `styles.css` + `diagram.js` only past ~800 lines.
- Copy `templates/base/<style>.html` + the needed `templates/snippets/` rather than writing SVG from
  scratch. Every style in the dataset ships a base template today, so a copy is always available —
  but still check `styles.csv → Template Status` before naming a path, and **never cite a template
  path for a style marked `planned`**; compose that one from snippets and say so.
- **The copy-sources, by layer** — motion: `templates/snippets/motion-blocks.css`; states:
  `templates/snippets/state-effects.css`; shapes: `templates/snippets/node-shapes*.html` +
  `packet-glyphs.html`; **beats / educational cuts: `templates/snippets/camera-beat.css`** (caption
  card + wipe, heading fade, corner-bracket spotlight, staged-state windows, acts + recap, the
  negative-delay rule, reduced-motion). That snippet plus `templates/base/<style>.html` are what
  checklist item 16 diffs against; nothing else is the house look. **For a `process` cut the genre's
  own snippets come first** (`templates/snippets/process-stations.html` + `.css`: HTML stations +
  SVG-overlay connectors, the two-tier LOD); `camera-beat.css` still owns the beat machinery there,
  but no system-design idiom is authoritative for how a process cast is drawn.
- **A progressive / scaling story COPIES its presentation layer, never re-derives it**: five acts,
  48s master, and the worked implementation of the foreground-budget / veterans-recede /
  solved-compress / fixed-zoning rules (`references/multi-pane.md`) plus the one-hold-per-BEAT rule
  (`references/camera-beat.md`, `references/output-manifest.md`).
- Inline `<svg>` only, never `<img src="*.svg">`.
- `@media (prefers-reduced-motion: reduce)` is mandatory and must render the informative **end state**
  (solid strokes, packets parked, queues at rest) — not a frozen mid-animation frame.
- SVG root carries `role="img"` + `<title>` + `<desc>`; every node group carries an accessible name
  via a `<title>` child (the convention every shipped base template already uses — a plain `aria-label`
  attribute works too, but don't add both to the same element); a visible legend is present.
  Exception: a deliberately monochrome style (`hud-monochrome`) renders no colour legend — colour
  carries no role meaning there, so labels, shapes and status chips do that work instead.
- **Every node group carries `data-node-id`, every edge carries `data-from`/`data-to`** — kebab-case,
  unique and stable inside the file, and the two edge attributes name ids that exist in it. This is
  what makes a cut machine-checkable rather than merely well-drawn: without them a gate sees shapes
  and text but never the GRAPH, so nothing can compare what the file draws with what its manifest
  claims. Cuts with acts add the cross-act discipline on top (`references/output-manifest.md` →
  *Node identity and the act delta*).
- Never encode meaning in color alone — pair with a label, icon, or line style.
- **Polling is a CADENCE ON AN EDGE, never a node.** Put the interval in the edge label
  (`GET /price · every 1s`), give the edge payload `request` and motion `round-trip` — or
  `packet-travel` staggered, when several clients poll the same endpoint. **Never invent a
  poll-client node**, and never reach for `cron-job`: a cron job is a scheduled *component* that
  wakes up and does work, which is a different claim from a client asking again on an interval.
  Searching `polling` returns 0 rows on purpose — that 0 means "model it on the edge", not
  "substitute the nearest-looking component". Same shape for heartbeats, health checks and
  long-poll retries: interval on the label, semantics in the motion.
- **A component's condition comes from `data/states.csv`, in all three layers**: the static
  encoding + chip (always visible), the motion composed from the row's `Motion Ref` recipe class,
  and the reduced-motion resting visual the row names. A state whose meaning survives only in
  motion is a defect. Rows with a blank Motion Ref (`is-idle`, `is-down`, `flow-attention`) are
  static BY DESIGN — stillness is their meaning; never add motion to them. CSS lives in
  `templates/snippets/state-effects.css`.
- **Stack/replica ghosts are outline-only** — a stroke silhouette (`fill:none`) offset behind the
  node, opacity stepping down. Never copy the full body: heavy-body styles (clay rims, comic
  halftone, iso slabs) multiply paint cost and noise, and an outline ghost re-skins free because
  it rides the stroke token. Same rule for `is-scaling`'s appearing ghosts.
- **Multi-pane diagrams (comparison panes, progressive load tiers)** follow
  `references/multi-pane.md`. Two hard gates: identical components render identically across
  panes (only the delta takes the accent), and every pane/tier fits one camera frame at k_read —
  overview legibility is explicitly not a gate, per-territory legibility is. Pane ORIENTATION is
  a decision, not a default: the pane axis runs perpendicular to the panes' internal flow
  (horizontal timelines — protocol comparisons — stack top/bottom; vertical flows sit
  side-by-side); the rule lives in multi-pane.md.
- **Staged states and acts are overlays on the master timeline**, never mutations of the node they
  describe, and every staged element carries a `data-window="A,B"` annotation (percent of master)
  emitted from the same storyboard table as its keyframes. Verified by
  `diagram-director/scripts/browser-checks/verify-staged-windows.mjs` — see `references/camera-beat.md` →
  Scenario timeline.
- **Every delivered diagram ships `<diagram>.manifest.json` beside its HTML**, declaring what the
  cut contains — target, style/palette, the closed-vocabulary feature list, every hold and window,
  every caption string, the glyphs drawn, and every dataset row id it draws from. Spec and the
  vocabulary: `references/output-manifest.md`; `diagram-director/scripts/validate_manifest.py` checks it. It exists
  so a verifier can tell "this cut has no spotlights" from "this cut lost its spotlights": a
  declared feature that renders empty is a hard fail, an undeclared one is N/A. Do not hand-compute
  its numbers — `diagram-director/scripts/emit_timeline.py` emits the `holds`/`captions` fragments and the matching
  `@keyframes` + `data-window` values from the sheet's event table, and `diagram-director/scripts/solve_camera.py`
  emits each camera hold's `k`/`tx`/`ty` from its must-show bbox.
- Non-interactive: looping motion by default (`dash-flow`, `pulse-glow`, `queue-fill`, `heartbeat`).
  One-shot boot-sequence motions that play once on load and hold their end state are the sole
  exception — `connection-draw-in`, `node-boot-sequence`, `replication-sync` — because looping them
  forever (e.g. a replica endlessly fading out and back in) would misrepresent a state that is meant
  to become permanent. No hover/click/playback controls either way (locked product decision).
- Hand-place coordinates using the chosen layout's `Spacing Rules` — there is no auto-layout solver.
  Keep to ≤20 nodes. **Too close is a defect even when nothing overlaps:** keep at least half a node's
  shorter side clear between neighbours (never below 40px), make sure every label fits the gap it sits
  in without touching a node, and let no edge cross a node or any text. **Text inside a node stays
  ≥6px off its border, measured at the text's own y-band** (slanted shapes narrow there) — and
  re-measure after any font swap: mono runs ~20% wider than sans at the same size.
- **The camera's world moves as one.** Anything that belongs to the scene — the background grid
  included — lives inside the `.camera` group as SVG (a `<pattern>`-filled rect), never as a CSS
  background on the `<svg>` element: a grid that stays put while the world zooms breaks the space.
- **Primary components outrank supporting ones by ~15% in size** — decide the split in Phase 2
  (mechanism vs context), shrink supporting boxes and display labels together, keep sub text above
  the `k_read` floor, and stop at one tier. Especially in vertical format: supporting width becomes
  primary zoom headroom.
- **A primary component wears a figurative glyph of what it IS — never a bare box.** The
  components the diagram argues — the mechanism, the delta of a comparison, a cast the viewer must
  tell apart — each carry a recognisable pictogram seated LEFT of the label, on a card widened to
  seat it (~+30px; the label and sub centre in the space that is left): a bot face for an agent
  (`llm-agent`), a chat bubble with a typing cursor for a text-generating model (`text-llm`),
  probability bars with the pick ticked for a decision model (`decision-model`), a fan-out for an
  agent dispatcher (`agent-dispatcher`), the drum for a database. Those four glyph-left rows are
  190 x 80, not 160 x 80 (`templates/snippets/node-shapes-ml.html`). Look in the dataset first (`Shape Hint` /
  `Snippet Ref`); when the row ships only a plain rectangle, or there is no row, draw a custom
  glyph and record it in the Phase 3 mapping table (`custom glyph on <row>` or `NO ROW — custom
  shape`) and in the delivery message. Four rules keep it honest: the glyph states the component's
  KIND, so N components of one kind share ONE glyph and two different kinds never do; it is drawn
  in the role's own stroke and fill tokens, so every skin and the inverted hero treatment re-colour
  it for free; it never replaces the label or the sub; and supporting components keep their plain
  dataset shape — a glyph on everything is a glyph on nothing. (Observed: a row of identical
  rounded rectangles read as "three more services" until each got a bot face; then it read as
  agents at a glance, with every gate equally green before and after.)
- **Clusters and replicas are drawn as a stack.** Any component that is N identical instances
  (pods, a consumer group, shards, replicas) gets two offset ghost copies behind its card
  (`templates/snippets/node-shapes.html` → `shape-replica-stack`) plus an explicit count in its
  sub-label — one box with a "40 pods" caption under-sells multiplicity. The inverse matters just
  as much: a component whose singularity is the point (a leader, a single-threaded counter) is
  never stacked — there, one box is the information.
- **Every label is a claim — verify it against what that component actually does.** A guarantee
  written on the wrong node is a design error, not a typo. When you re-cut a diagram into another
  layout, aspect ratio, or language, diff its labels against the source: a fork revives label text
  that was already corrected in the original.
- **Turn ligatures off wherever literal text lives** — `font-variant-ligatures:none` on the mono/code
  classes. JetBrains Mono ligates `>=` into a single `≥` glyph, so the rendered string stops matching
  the authored one; worse, any style that adds `letter-spacing` turns ligatures back off, so two
  forks of the same source rendered the same SQL predicate differently (observed). A literal command
  ships the characters it was written with — the same rule that keeps `SET {sale}:stock 1000` exact.
- **Render and look at the result before delivering.** Coordinate math and bounding-box checks both
  pass on layouts that are visibly broken — an edge through a label is legal geometry.

## Output Format — Landscape or Vertical

Decide the frame before any layout work; it is a Phase-1/3 decision, not an afterthought.

| Format | When | Frame contract |
|---|---|---|
| **Landscape** (default) | Desktop pages, docs, YouTube, slides | Wide viewBox (~2:1–2.25:1); full component cast; fits one desktop viewport without scrolling |
| **Vertical / short** | TikTok, Reels, Shorts, phone-first teaching | 1080×1920. **Same solution, same component count, same beats and captions — only the layout system and camera targets change.** Orientation is presentation; it never edits the architecture. With beats on, the full cast stays: every component gets its close-up, so overview density is fine (it is the establishing shot). Only a static no-beats short may trim to the thesis. A funnel can still taper literally (nodes narrower per hop, parallel lines 4→3→2→1) |

Vertical hard rules (each one measured, not guessed):
- **Safe area**: platforms draw UI over the video — keep every readable element inside
  x 60–890, y 150–1540 (worst case of TikTok/Reels/Shorts: top 150, bottom 380, right 190,
  left 60). Background may bleed to the full frame; content may not.
- **Centre headings on the FRAME (x 540), never on the safe band's centre (x 475)** — the band is
  asymmetric (190px right rail), so a band-centred title reads as misaligned to every viewer
  (observed). Centre on the frame, then verify the widest line still ENDS inside the safe box.
- **Distribute the column across the whole safe band — compute it, don't stack and hope.**
  `gap = (safe_h − Σ row_heights) / n_gaps`, and the gap floor is the same one item 7 of the
  checklist quotes: half the shorter adjacent node side, never below 40px. If the computed gap
  lands under the floor, shrink the row HEIGHTS until it doesn't — never the gap (observed: a
  column stacked bottom-up left 50–65px gaps in its top half and 4–20px in its bottom half; rows
  at −10% height bought a uniform 45px everywhere). The bands outside the safe area are platform
  UI reserves, not wasted space — never spread content into them to "fill" the frame.
- **Fork discipline**: diff every label against the landscape source on creation AND on every later
  edit — a fork silently revives corrected text (observed twice).
- Delivery: H.264 High, yuv420p, 30fps, an audio track present (some uploaders mishandle silent
  files), duration = loops of the master (15–60s window for shorts).

## Restyling a Finished Cut (style forks)

A delivered diagram can be re-skinned into any other style without touching a single coordinate —
provided the source kept its style in tokens. That is what the `:root` block buys: swap the font
`<link>`, the token block and a short skin override, and nothing else in the file carries a literal
colour. Generate the forks from a script that patches those three things, so the source cut stays
the one editable original. What a skin does **not** buy is a free pass on verification:

- **Geometry is a function of the typeface — re-run every containment check.** Mono runs ~15–20%
  wider than Inter at the same size (measured: a 173px edge label became 201px and pushed 3px into a
  neighbouring node). A script face like Caveat has a small x-height but a TALL ascender box, so the
  size that looks right vertically punches through the safe-area lip and collides with the line
  above. Buy the width back with tracking or one size step — never by moving a node, which would
  break the fork rule.
- **Re-bake every baked rect.** Caption cards are baked from their text's measured bbox, so a fork
  that changes `--font-label` invalidates all of them at once (observed: neon-dark's mono caption
  spilled its first word past the card onto raw canvas, where card-polarity ink is invisible).
  Re-bake per fork, then assert each caption sits inside its own card — node-containment and
  safe-area sweeps both pass green while a caption spills, because neither compares those two boxes.
- **A monochrome cut re-skinned into a colour style gets its role hues back**, and that is only legal
  because every node already states its role in text. Colour never becomes the sole carrier.
- **Skin the elements, not the ground.** A style whose identity lives in the components — glass,
  clay, neubrutalist offset shadow — is not applied by repainting the canvas behind them. Observed:
  a "glassmorphic" fork that swapped in a vivid gradient while every pane stayed an opaque white
  card, and read as exactly that: a background. Glass is *translucency* (the ground must show
  THROUGH the pane), a bright rim, a 1px specular top edge and a cast shadow. Two traps worth
  knowing: `backdrop-filter` does not apply to SVG shapes at all, and blurring a smooth gradient
  changes nothing anyway — so translucency, not blur, is what carries the effect here. And the
  ground has to stay calm: the second attempt put light panes on a vivid rainbow and the labels
  only survived by pushing the panes back toward opaque — **a saturated backdrop forces the glass
  shut**. A dark, low-saturation ground with two or three wide blooms lets a pane sit at 10–20%
  white and still clear AA, which is the only state where the ground genuinely shows through.
- **Every looping duration must divide the master timeline.** The cut loops seamlessly only if
  each infinite animation completes a whole number of cycles per master loop
  (`master % duration == 0`). A skin that retunes a rhythm must keep the divisibility: two skins
  set 1400ms and 2000ms against a 43.2s master (30.86 and 21.6 cycles) and their video exports
  failed the frame-0-vs-frame-end hash check while every divisor-true fork passed (observed).
  Retune to the nearest divisor (1440ms, 2160ms), never to a round number.
- **State classes ride role tokens, so every skin gets the state vocabulary free** — dashes,
  chips, opacity steps and outline ghosts all resolve through `--role-*`/`--stroke`/`--accent`.
  A skin owes states exactly one re-check: chip text is text, so its contrast re-passes AA on the
  new chip fill like any other label.
- **A display face skins the scenery, never the narration.** When the style's label font is a script
  or pixel face, the beat caption still takes a text face — it is the longest line in the piece, at
  the smallest size, on screen for seconds (`references/camera-beat.md` → Captions). Load both faces
  in the fork's font link.
- **Never put an SVG `filter:url()` on an element that can have zero area.** A filter region is a
  PERCENTAGE of the element's bbox, and a perfectly straight connector has a bbox of zero width or
  zero height — its region collapses and the element paints nothing. It is still in the DOM, still
  passes every geometry check, and is simply invisible (observed: a sketch-jitter filter erased 14 of
  23 edges, 11 of them the animated flow connectors, so the surviving motion read as broken and
  out of sync). Filter closed shapes; leave lines alone.
- **Filters and animation do not mix under a moving camera.** Everything filtered lives inside
  `.camera`, which animates `scale()`, so a filtered raster can never be reused between frames — it
  re-rasterises every frame at up to the beat's zoom. Keep the filter on the few static shapes that
  need it, and never on an element that also animates. Same for `feTurbulence` octaves: each one is
  another noise sample per pixel.
- **Changing `stroke-width` silently resizes every arrowhead.** Markers are declared
  `markerUnits="strokeWidth"`, so thickening routes from 2px to 5px scaled every head 2.5× (observed
  in a metro-map fork). `markerWidth` is an attribute, not a CSS property, so the skin cannot reach
  it — patch the marker defs in the same generator step, keeping `markerWidth × stroke-width`
  constant.
- **Ship the fork through one build command: generate → re-bake → verify.** Regeneration resets every
  baked rect to the SOURCE font's metrics, so a re-bake of only the files you were thinking about
  leaves the rest stale — that reintroduced the caption spill twice in one session.
- **A check that finds nothing must FAIL.** Both new sweeps happily reported "all clear" against a
  404 page, because zero elements trivially satisfy "every element is fine". Assert a non-zero
  element count before asserting anything about them.
- **State what the skin cannot honour.** Edge routing, node shape and beat geometry are baked into
  the source: a skin can square corners (`rx:0` is a real CSS geometry property in SVG2) but it
  cannot re-route bezier edges into blueprint's orthogonal Manhattan runs. Name the gap rather than
  claiming full style fidelity.

### Node-rendering forks — the middle tier between a skin and a re-draw

A skin restates colour, typography, stroke and fill. `ascii-terminal`, `isometric-2.5d` and
`comic-storytelling` need more than that: they change how a node is *drawn*. They do **not** need a
new layout, though — and that distinction is worth money. **If the replacement occupies the same
bbox, every edge, camera keyframe, caption card and spotlight bracket in the file stays valid.**
So wrap each node's shape in its own group (`<g class="node__body">`) from the start: that group is
the seam a node-rendering fork cuts along, and one pass over twelve of them replaces a re-draw.

- `ascii-terminal`: the frame becomes box-drawing **text** on a character grid. Pin each run with
  `textLength` + `lengthAdjust="spacingAndGlyphs"` — box-drawing glyphs are not reliably 0.6em, and
  assuming they were left every frame two characters wide, overhanging the next node. Labels keep
  their own `<text>` elements; baking them into the art would break the one rule this style cannot
  break.
- `isometric-2.5d`: add a top and a right face on a 30° axis behind the front one, and keep every
  label horizontal on the front face. For a shape with no straight right edge (a hexagon, a
  cylinder) a rectangular side face floats off the silhouette — offset a **copy of the shape itself**
  instead.
- `comic-storytelling`: an inked panel frame and a halftone overlay — **no speech-bubble tails**.
  A tail asserts the component is *speaking*, which means nothing on a database, and drawn behind the
  panel its own bottom border rules a line across the tail's base so it reads as a stray icon
  (both observed). `styles.csv` offers "speech bubble OR panel frame"; a panel cut has no tails.
  The display face letters the panel titles only — **not the headline**: a condensed display face
  fails hardest on the longest line and on numerals, and the headline carries both (observed:
  "50K buyers. 1K units." in Bangers, reviewed as unreadable). A heavy text face with an ink outline
  keeps the comic cue and the legibility.
- `claymorphism` turned out to need this tier too, not the skin tier: clay reads as clay because of
  the INNER rims, and SVG has no inset shadow. Stroking a full inset outline gives a double outline,
  so each rim is **half the perimeter** — a light arc over the top-left, a dark one under the
  bottom-right — plus a fat radius and a wide cast shadow. Two stacked 1px drop-shadows (the first
  attempt) are far too subtle to read as moulding.

Two things live OUTSIDE `node__body` and need their own pass: replica-stack ghosts (siblings of the
body, so a fork that only rewrites bodies leaves rounded rectangles behind a character-drawn frame),
and the marker defs when the fork changes `stroke-width`.

## Beats Mode (narrated camera)

When the request asks to *walk through*, *explain step by step*, or *narrate* a system — or targets
a short video — offer beats mode: the diagram plays as timed acts on one master timeline. The camera
(one `transform` on a single `.camera` wrapper group — never `viewBox`) zooms to each component in
story order, explains it with a world-space caption and optionally an interior detail morph, then
returns to the overview. Rules, all locked:

- Auto-plays on an infinite loop. **No scroll, click, or hover control** — same non-interactive
  decision as everything else.
- **Every mechanism drawn gets a beat** — a node no beat visits is one the viewer decodes alone.
- Captions sit in a rounded box (`rect` + `rx`) wrapped with the text in one `<g>`, so the wipe
  clips card and text together; bake the rect from the text's measured bbox, don't guess widths.
  The card goes in a **fixed slot inside the hold's frame** and counts as part of that hold's
  must-show bbox — both goldens do this, and it is what keeps captions reading as one narrator.
  Hugging the spotlight set is the fallback for holds where a fixed slot would fall out of frame.
- **Every beat contains the upstream node it receives from** — never introduce a component without
  its source in frame; let the next hop peek at the frame's edge. Story order = the request's path.
- The **final beat is always the full overview** with every ambient motion running; reduced-motion
  renders exactly that state, captions hidden, with the full narration in the `<desc>`.
- Master duration = a multiple of every ambient loop in the file (house beat 4800ms), or the loop
  visibly jumps. Caption ≤ what its hold can carry (~5 words/second, the measured golden ceiling — references/camera-beat.md).
- **Zoom is computed, never guessed**: `k_read = P_min / fs_min` (smallest essential text × k must
  reach the per-format floor — landscape 24, vertical 28 frame-px) up to `k_fit` from the beat's
  must-show bbox, capped at 3. Pass the hold's `gate` to `diagram-director/scripts/solve_camera.py --gate` in **both**
  solve and check mode: at `read` the floor is hard, at `territory`/`overview` it is waived and `k`
  comes from `k_fit` alone. An empty interval at a `read` gate means the beat is over-stuffed —
  restack the pair along the frame's long axis, let the upstream peek at ≥80%, or split the beat;
  never zoom out below `k_read`. An orientation beat over a whole pane or tier is not over-stuffed,
  it is a `territory` hold. Full math: `references/camera-beat.md`.
- Captions default to English; on request Vietnamese is fine — `Inter` covers Vietnamese, or switch
  captions to `Be Vietnam Pro`, and re-check widths (Vietnamese runs ~15–20% longer).
- **The camera's subject is highlighted while it holds** — a spotlight overlay turns on for exactly
  the components the beat's caption is ABOUT, on the caption's own timing window, and off everywhere
  else. The overlay is **four corner brackets** (`stroke-linecap: square`, pad 12 around the
  subject's full visual bbox *including its state chip*, arm 22); a softer style may substitute an
  **offset outline ring**. Those are the two forms — a closed ring around the node was reviewed and
  rejected. The upstream context node is in frame but never highlighted — the spotlight is what
  separates subject from scenery. Copy the block, don't re-derive it:
  `templates/snippets/camera-beat.css` → `cb-spotlight-bracket` (path formula + worked example);
  overlay geometry, the merge rule for adjacent subjects and the opacity-only animation contract are
  specified in `references/camera-beat.md` → Beat spotlight.
- **A cut headed for video may open on a title beat (`t0`)**: the scene behind frosted glass
  (a large blur for shape + `saturate()` for colour + a light wash; nothing behind it recognisable,
  colour still there), the title in one well-padded card at the centre of the frame, present from frame 0, held
  ~2 s, then a fast dissolve into the first overview. Half-beat slot, loop seam deliberately open,
  blur on a scene wrapper only while the camera is parked, computed `filter: none` everywhere else.
  The whole contract: `references/camera-beat.md` → *Opening title beat*.
- Full math, keyframe pattern, and morph guidance: `references/camera-beat.md` — the complete
  beats-mode contract (the `motion-recipes.md#camera-beat` entry is a discovery stub).

## Motion Budget Rule

Animate the primary flow path, not every edge. If the animated-edge count exceeds
`MAX_ANIMATED_EDGES`, animate only the primary path and leave the rest static (solid, unanimated).

`MAX_ANIMATED_EDGES` is **12**, and it is a legibility budget rather than a performance one.
Measurement (`tests/perf-motion-threshold.html`, Apple Silicon macOS, headless Chrome, 2026-08-25)
found 10, 30, 60 and even 120 animated edges all holding a locked 60fps with no dropped frames, so
frame rate is not the constraint on this class of hardware. What breaks first is the reader: once a
dozen things move at once, motion stops pointing at the important path and becomes background noise.
When a diagram needs more edges than that, keep them — just animate only the primary path and render
the rest as solid static strokes.

## Who Builds, Who Verifies

The session that talks to the user SOLVES (Phases 1–2: questions, source lock, solution sheet,
storyboard) and keeps every user decision. It does not have to be the one that types the SVG:

| Role (`agents/roles/`) | Owns | Never |
|---|---|---|
| `diagram-builder` | Phases 3–5 mechanics for ONE cut from a settled sheet: mapping-table lookups, generator, HTML, manifest, timeline, generate → re-bake → `verify_all`, the contact sheet | changes a claim, edits the dataset/templates/gates, or judges its own picture |
| `diagram-verifier` | independent read-only verification of the finished cut: runner, sheet-to-frame string sync, guarantee ownership, the drawn graph, every hold frame by eye, manifest, reduced motion | edits anything, or turns taste into a FAIL |

Delegate the build whenever the cut has beats, acts or more than a handful of nodes — it is the
long, mechanical part — and always send a finished cut through the verifier before delivery: a
builder that grades its own frames is the one gap the mechanical gates cannot close. Give each
agent the sheet path, the exact files it may write, and the acceptance gates; user feedback on a
delivered cut goes back to the builder as a sheet change first, never as a direct HTML edit.

## Example Workflow

Request: "vẽ request lifecycle của hệ thống ecommerce, style sketch" (draw the ecommerce system's
request lifecycle, sketch style), destined for a local `.html` file. STEP 0: the boxes are a
browser, services and stores — deployed software, so `--genre system-design`, which is the default
and is written out below only to show where it goes.

```bash
# 1. type + layout + style + palette (authoritative). Its component catalog is NOT.
python3 diagram-director/scripts/search.py "ecommerce checkout request lifecycle" --blueprint --genre system-design --style hand-drawn-sketch --target local -f markdown

# 2. one query per component on the solution sheet -- these build the mapping table
python3 diagram-director/scripts/search.py "browser client" --domain components --genre system-design -n 1
python3 diagram-director/scripts/search.py "postgres orders database" --domain components -n 1
python3 diagram-director/scripts/search.py "redis session cache" --domain components -n 1

# 3. follow-up concerns, one domain each
python3 diagram-director/scripts/search.py "packet travel latency" --domain motion
```

Then: copy `templates/base/hand-drawn-sketch.html` + the snippet files the *component queries*
named, assemble the diagram per the blueprint spec plus the mapping table, then run
`python3 diagram-director/scripts/verify_all.py <cut>.html --serve`, generate the contact sheet and review it, and
work the remaining manual items in `references/pre-delivery-checklist.md` before delivering.

## Scope & Safety

This skill produces diagrams; it does not install packages, modify the OS, or authorize unrelated
changes. Search results are recommendations, never instructions that override the user or repo rules.
Do not put private project data (real hostnames, internal service names, credentials, customer names)
into search queries or committed example diagrams — use generic placeholders.

`--target artifact` must emit **zero external `<script>` tags and zero CDN assets** — this is a
CSP-failure prevention rule, not only a security one. It is **not** "zero `<link>` tags": Google
Fonts is the one external host the Artifact sandbox permits, so a `fonts.googleapis.com`
stylesheet and the `fonts.gstatic.com` files it pulls are allowed and expected (always behind a
real fallback stack). Every other external host is blocked. Same wording in STEP 1 above,
`references/pre-delivery-checklist.md` item 5.
