Checkout request flow

metro-map style · three routes through six stops · 45 and 90 degree bends only

  • R1 checkout — synchronous request path (solid)
  • R2 cache — read-through lookups (solid)
  • R3 events — asynchronous publish (dashed)
  • client — browser, mobile, or device
  • service — application code we own
  • data — database, cache, object store
  • async — queue or worker (dashed route)
  • external — third party we do not run
  • error — failure path (long-short dash)
  • infra — platform and observability

Reading the map: a circle is an ordinary stop, a diamond is an interchange where routes meet, and a dashed route is asynchronous — none of those three depend on colour. The bright strand marching inside a route means traffic is flowing on it and a travelling dot is one in-flight request. With reduced motion enabled the strand becomes a solid inner highlight and the dots park at their destination stops, so the map still says which routes are live and where the traffic ends up.
