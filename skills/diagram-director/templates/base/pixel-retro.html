CHECKOUT REQUEST FLOW

pixel-retro style · layered left-to-right · six components · stair-stepped connectors, no diagonals

  • client — browser, mobile, or device (tag: CLIENT)
  • service — application code we own (tag: SERVICE)
  • data — database, cache, object store (tag: DATA)
  • async — queue or worker (tag: ASYNC, dashed edge)
  • external — third party we do not run (tag: EXTERNAL)
  • error — failure path (tag: ERROR, long-short dash)
  • infra — platform and observability (tag: INFRA)

Reading the motion: everything moves in whole grid cells, never fractions — marching dashes step 4 units per tick to show traffic flowing, a square packet hops 20 units per tick as one in-flight request, the hard halo blinking on and off means that sprite is actively processing, and the bar fills one block at a time for queue depth. With reduced motion enabled every one of those renders as its end state — solid strokes, packets parked at their destination, the halo held on, the queue bar at its resting depth — so nothing here depends on animation to be understood. The all-caps tag across each sprite repeats its role as text, so the diagram also survives greyscale.
