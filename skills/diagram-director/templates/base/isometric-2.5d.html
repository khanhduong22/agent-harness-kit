Checkout request flow

isometric-2.5d style · 30° isometric grid · six extruded blocks

  • client — browser, mobile, or device
  • service — application code we own
  • data — database, cache, object store
  • async — queue or worker (dashed edge)
  • external — third party we do not run
  • error — failure path (long-short dash)
  • infra — platform and observability

Reading the picture: every component is the same extruded block, so depth is decoration — type is carried by the badge on the top face, the label and the sub-label, never by the 3D or by colour. Reading the motion: marching dashes mean traffic is flowing on that connector, a moving dot is one in-flight request, a pulsing block is actively processing, and the gauge on the side of message-queue is queue depth. With reduced motion enabled every one of those renders as its end state — solid strokes, dots parked at their destination, the gauge at its resting depth — so nothing here depends on animation to be understood.
