Checkout request flow

neon-dark style · layered left-to-right · glow limited to the primary path

  • client — browser, mobile, or device
  • service — application code we own
  • data — database, cache, object store
  • async — queue or worker (dashed edge)
  • external — third party we do not run
  • error — failure path (long-short dash)
  • infra — platform and observability

Reading the motion: marching dashes mean traffic is flowing on that connector, a moving dot is one in-flight request, a pulsing node is actively processing, and a filling bar is queue depth. Glow marks the primary request path, never a status. With reduced motion enabled every animation renders as its end state — solid strokes, dots parked at their destination, a static glow instead of a pulse, and the queue bar at its resting depth — so nothing here depends on animation to be understood.
