Checkout request flow

hand-drawn-sketch style · whiteboard draft · six components

  • client — browser, mobile, or device
  • service — application code we own
  • data — database, cache, object store
  • async — queue or worker (dashed edge)
  • external — third party we do not run
  • error — failure path (long-short dash)
  • infra — platform and observability

Reading the motion: marching dashes mean traffic is flowing on that connector, a moving dot is one in-flight request, a pulsing node is actively processing, and a filling bar is queue depth. With reduced motion enabled every one of those renders as its end state — solid strokes, dots parked at their destination, the queue bar at its resting depth — so nothing in this diagram depends on animation to be understood.
