Event-driven order pipeline

flat-minimal style · hub and spoke · queue and workers fan out from a central event bus

  • async — bus, topic, or dispatcher (dashed edges = at-least-once)
  • service — publisher or consumer we run
  • infra — observability (metrics collector)
  • error — dead letter queue (long-short dash)

Reading the motion: the event bus and the worker pool pulse because they are the two nodes actively processing work; everything else is passive infrastructure. Every edge fans out from the single hub — there is no direct line between any two spokes, and no fanout ever skips the dead-letter-queue path for messages that exceed their retry budget. The hub is drawn one size larger than its spokes on purpose: size marks the subject, it is not decoration. With reduced motion enabled both pulsing nodes render at a fixed, steady glow instead of animating — nothing here depends on animation to be understood.
