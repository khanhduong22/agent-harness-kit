## Phase 1 — answers that fixed the architecture (user, 2026-09-21)

- Workload (revised 2026-09-21): dispatching an incoming ticket to the right agent — customer
  care, sales advice, complaints — with complaint classification as one of the questions.
- Format: vertical 9:16.
- Scale + autonomy: assume ~50K tickets/day; refund / plan cancellation always need human approval;
  the auto lane only classifies, routes and answers FAQ-style tickets.
- Revision (same day): two acts — ACT 1 the same agent on a traditional LLM, with beats that name
  its limits; ACT 2 with Jev. Title is the comparison. Jev's node must stand out. No bare `p` / `τ`
  on the frame: spell `prob.` and `threshold`.

## COMPONENTS

The problem, restated (user, 2026-09-21): a ticket arrives and the system must decide WHICH AGENT
takes it — customer care, sales advice, complaints — and whether it is a complaint at all. The
earlier cast (one agent resolving a ticket end to end) followed the source article's example too
closely; this is the general dispatch problem it was an instance of.

## FLOWS

- ACT 1: customer → ticket API → state builder (← `facts`) → LLM router → `“sales”` → dispatcher →
  `“support”` / `“sales”` / `“complaint”` → the agent. complaint agent → `severe` → human desk.
- ACT 2: … state builder → Jev gateway (← `ask`) → dispatcher (← `thresholds`) → `confident` →
  support or sales agent, `complaint` → complaint agent; `unsure ⇄ agent` with the triage LLM;
  support and sales agents → `resolved · handed back` → outcome log ← `verdict` ← human desk (the
  complaint agent logs the same way; its edge is NOT DRAWN — it would cross the human desk — so on
  the frame its outcomes reach the log through the desk's `verdict`); outcome log →
  `outcomes` → calibration → `tune thresholds` → registry.
- Both acts: the dispatcher finds a newer `state_version` (the customer wrote again while the
  decision was being made) → `stale → rebuild` → state builder. The reply returns through the
  ticket API (`ticket · reply`, drawn two-way).
- ACT 2 failure path, drawn: Jev gateway → `timeout` → triage LLM.

## GUARANTEE OWNERSHIP

| guarantee | owner | mechanism |
|---|---|---|
| direct hand-off only above the threshold | dispatcher | deterministic code, thresholds from the registry |
| no assignment on a stale state, no double assignment | dispatcher | CAS on `state_version` + idempotency key on the hand-off |
| the agent list is never closed | registry | `other` on the Choice → triage LLM |
| a vendor outage never blocks a ticket | Jev gateway | timeout → triage LLM |
| risky actions always reach a person | human desk | severe complaints and refunds queue for approval, SLA timeout escalates |
| thresholds follow reality, including the confident band | calibration + human desk | outcome bins per question and type; hand-backs as the misroute signal; random audit sample against selective labels |

Solution audits — race: Jev decides on state v, the customer may write again before the hand-off →
CAS in the dispatcher. Recovery: Jev timeout → triage LLM; a hand-back re-enters at the state
builder; desk SLA → escalate; a crash between CAS and hand-off → idempotency key. Pre-condition:
registry and thresholds are seeded from an offline eval set of past tickets with their final agent,
and direct hand-off runs in shadow mode first — the first ticket never initialises a threshold.

  Style and palette taken as returned.

  `layered-tb` replaces it.
- Acts without the `act-delta` feature: the delta table above is documentation; no retirement ghost

  or the highlight is wrong"). Diagnosis: every hold was geometrically right, but a 9:16 frame at
  k≈1.9 shows six rows at once, the hero-coloured Jev node out-shouted the corner brackets in every

  must-show bbox stays in the safe rect; (2) every card sits in the gap next to its own subject,
  and must-show sets no longer drag in a far endpoint (a trunk may leave the frame); (3) while a
  spotlight is lit, a paper-coloured wash at 60% covers the world except a bracket-sized window over
  each subject. camera-beat.md says zoom makes a veil unnecessary; that holds in landscape, not here.

**Follow-up (same day, CROSS-ENGINE DEFECT): the frost was Chrome-only. Rebuilt on a native SVG filter.**

**Root cause.** The user reviews in **Safari (WebKit)** and saw no blur in any of the first three
passes — only the wash. **WebKit does not apply CSS `filter:` FUNCTIONS to elements inside an
`<svg>`**; it honours them on HTML elements and on the root `<svg>` only. So
`.scene-blur{filter:blur(…) saturate(…)}` and its animated keyframes were silently dropped there,
while Chrome — which is what every gate, the contact sheet and the MP4 exporter run on — rendered
them. Every check and every frame reviewed was right *and* the cut was broken for the person
looking at it. **A CSS filter function is not a cross-engine technique for an SVG cut; a native
`filter="url(#…)"` attribute is.** That is the general lesson, not a fact about this cut.

- **`<filter id="frost">` in `<defs>`**: `filterUnits="userSpaceOnUse" x="-400" y="-400"
  width="1880" height="2720" color-interpolation-filters="sRGB"`, holding
  `<feGaussianBlur stdDeviation="130"/>` then `<feColorMatrix type="saturate" values="6"/>` — the
  same two stages, same order and same colour space as the CSS `blur(130px) saturate(6)` it
  replaces. SVG 1.1, so Safari and Chrome render it identically.
- **It is applied by ATTRIBUTE to a dedicated static backdrop group `g.frost`**, not to the scene:
  one `rect` per act-1 node at its real position and size carrying `data-role` (so it resolves the
  same `--fill`/`--line` tokens as the node), the act's edges as plain strokes, over an opaque
  paper ground. **No text, no `data-node-id`, no `class="node"`, no `class="edge"`,
  `aria-hidden="true"`** — `act_dom_scan`'s three readers are `<g class="act…" data-act…>`,
  `<g class="node[ "…>` and `<path class="edge…"`, and this group matches none of them, so
  `tier-identity` still counts *15 ids across 2 acts* and `legend-fact` is untouched. Under
  stdDeviation 130 an impression and the real cast are the same picture.
- **DEVIATION from the instruction, stated: the frost sits ABOVE the real scene with an OPAQUE
  ground, and the real scene is never faded.** The instruction was to fade the scene 0 -> 1 against
